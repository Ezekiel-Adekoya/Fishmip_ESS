## 2. Script 02 — the one to look at first

Two faults, and the second is the dangerous kind.

**`plankton_all` was never built.** The processing chunk returns one *wide*
table per group (`Year` + a column named after the group). The spin-up chunk
expects a single *long* table with `Year / val / variable`. Nothing bridged
them, so the chunk died on its first line and the 1861–2010 plankton files were
never produced. That is why 04's committed `.dat` existed but could not be
regenerated — the inputs were gone.

**`file_label` matched nothing.** It was keyed on the long names
(`Diatoms`, `Diazotrophs`, …) while `variable` carries the short ones
(`Diat`, `Diaz`, …), so every `filter()` returned zero rows.

Fixing only the first fault would have made 02 run **without error** and write
five empty CSVs. I added `stopifnot()` on the key set and a row-count and
contiguous-year check per file so that cannot recur.

## 3. Script 04 — the resource level (the substantive change)

The COBALT-derived resource, measured against the resource
`params_stage1_steady` was calibrated on, over the bins the model actually sees
(`w < w_pp_cutoff`):

| size band | before | after anchoring |
|---|---|---|
| < 0.001 g | ×4.59 | ×0.94 |
| 0.001–1 g | ×5.89 | ×1.21 |
| 1–4.19 g | ×7.23 | ×1.49 |
| 4.19–100 g | ×8.10 | ×1.67 |
| **total** | **×4.96** | **×1.02** |

This is not a fault in your spectrum construction — per-group biomass
conservation is exact to 6e-15, and a semi-chemostat resource tuned to balance
a fish community is not a prediction of plankton standing stock. The problem is
that the fish were calibrated against the lower level, so the ESM level
invalidates the calibration.

**Measured consequence.** A 100-year projection at mean 1861–1960 effort with
the resource held constant:

```
calibrated resource      B(0) 6.52  B(100y)  7.45 g/m2   drift x1.14
GFDL 1861, UNANCHORED    B(0) 6.52  B(100y) 32.74 g/m2   drift x5.02
GFDL 1861, ANCHORED      B(0) 6.52  B(100y) 10.00 g/m2   drift x1.53
```

The unanchored case reproduces what your 05 outputs actually show (36.9 g/m²
at 1961), so the mechanism is confirmed. Note ×1.14 of the residual ×1.53 is
the base model responding to spin-up effort differing from `initial_effort`,
not the resource.

**The fix** is one constant multiplicative factor (×0.206) applied to every
year and every bin, set so the 1978–1981 resource biomass below the cutoff
matches the calibrated resource. Being constant it is additive in log10, so it
cannot touch the slope or the year-to-year variation — both are asserted in the
script. `GFDL_resource_slope.dat` is unchanged; the intercept shifts by the
same constant.

This is a modelling judgment, not a bug fix, which is why it is in its own
commit (`a25138e`) — take it or argue with it independently of the rest.
The alternative would be to recalibrate the fish against the ESM resource.

**Left deliberately alone:** `fit_slope()` fits over every bin with
`dens > 0`, which includes the 55 extension bins it generated itself at exactly
slope `b`. So the self-consistent `b` is partly fitted to its own extrapolation
across 4.4 decades of size. This biases the *slope*, not the level, so it does
not affect the anchor — but it is circular and worth a look. I did not change
it because it would move `b` and that is your call.

The residual ×1.67 in the 4.19–100 g band is your deliberate extension standing
in for prey COBALT does not report. Now the largest remaining discrepancy.

## 4. Script 01 — spin-up cycle

`n_cycle` was 5. Plankton uses 10, and `Effort_spin_1861_2010.csv` is built on
10 as well (1960 repeats 1970, 1956–60 repeat 1966–70). So temperature was out
of phase with the other two forcings for the whole of 1861–1960 — a warm
spin-up year could sit against a low-plankton year for no physical reason.

The README's issue 1 says "align A's 5 and B's 10" without saying which way;
checking the effort file settles it — **01 was the outlier**, so it changed to
10, not 02 to 5. Verified afterwards that 1861 repeats 1961 in all three
forcings. The 1961–2010 bias-corrected data is untouched and the root
`Temp_by depth.csv` is byte-identical; only the constructed block moved.

I added a cross-check against the effort file that stops with a clear message
if the cycles ever diverge again.

Also: `library(ggplot2)` was commented out in the setup chunk but first used
~line 525, and only loaded at ~line 603, so both earlier plot chunks failed on
a clean run. Uncommented.

## 5. Script 05 — now unblocked, but read this before running

**It will silently use stale results.** The cache guard is
`if (file.exists(cache_f) && file.exists(cache_c) && !exists("force_resim"))`,
and the cached sims on disk are **older than the forcing**:

```
sims_with_fishing.RDS      2026-11-25 23:26
GFDL_resource_spectra.dat  2026-11-26 00:12   <- 46 min later
Temp_by_depth_spin.csv     2026-11-26 00:12
```

They were built on the unanchored 5x resource and the old 5-year temperature
spin-up. **Delete both RDS files or set `force_resim <- TRUE`**, or you will be
checking the calibration against the old inflated run and it will look like it
worked. The script's own comment admits the cache cannot detect changed params,
effort or forcing — worth making the guard compare file mtimes.

**`n_sims` was 10**, not 1 as the README says. Set to 1 at Julia's request for
a calibration check.

**`biomass_ts.RDS` is generated by a new script.** It was missing. The copies in
the sibling ESS repos are all identical and none is usable: 13 species under raw
upper-case survey names (`AMERICAN PLAICE`, `HERRING(ATLANTIC)`), including
Greenland Halibut, which is not in the model — they fail 05's own check that the
three pelagic species are present by name. The copy in
`Thermizer/August_2025/Ess_Thermizer_data/` is unreadable, possibly corrupt.

So `make_biomass_ts.R` rebuilds it from `LF_Biomass_Abund.csv`, reproducing 05's
own construction step for step (4VsW strata 443–466, 1970–2024, kg→g). Forage
catchability multipliers **are** applied (Herring ×50, Sand Lance ×3000,
Capelin ×200) — Julia's decision. Be aware this means `tpb` is compared against
survey values inflated up to 3000-fold. Those multipliers were tuned to balance
seal predation, not derived as catchability estimates. The script has an
`apply_forage_multipliers` flag if you want raw survey values instead.

**A column-name disagreement worth reconciling.** 05 builds the same survey
table internally around line 419 and renames the value column to `Biomass_Obs`,
but everything after the "Survey data" step (`obs_tcb`, `pel_obs_all`,
`obs_tdb`) sums a column called `Biomass`. So the `readRDS` is load-bearing
rather than redundant, and the two halves of the script disagree. One of them
should change.

## 6. Calibration check (`calibration_check.R`, Julia's script)

Worth recording because it tells you where *not* to look:

- Yields within 7% of target for 16/19 species
- Biomass within 2x for 15/19 — low: White Hake 0.27x, Thorny Skate 0.34x,
  Red Hake 0.42x, Longhorn Sculpin 0.47x
- All `erepro` < 1
- **Stable over 100 years at constant effort: all 19 species within 5%, none
  still moving**

So the catch overshoot is *not* a base calibration failure and not drift in the
calibrated state. That is what pointed at the forcing.

Against observations, before the anchor, modelled catch was high in every
decade — 2.7x (1970s), 3.2x (1980s), 3.8x (1990s), 2.3x (2000s), with spikes at
1981 (17x), 1989 (11x), 1999 (12x). Roughly flat rather than growing, which is
what ruled out progressive drift. Expect ~1.3–1.5x after anchoring, not 1.0.
